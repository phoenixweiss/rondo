Личный проект фронтенда для Anbernic RG34XXSP. Приставка мне очень понравилась, а подходящего для себя фронтенда я не нашёл — поэтому начал делать Rondo.

**Ранняя разработка.** Интерфейс и формат настроек могут меняться.

Базовая среда пакета — BaseOS 1.3.0. Rondo также проверен на RG34XXSP с BaseOS 1.5.2 (предварительный выпуск upstream). Настройки времени определяют платформу и наличие служб без привязки к номеру ОС; подробнее — в [совместимости](docs/compatibility.md).

**Bluetooth экспериментальный:** поиск и подключение доступны, но кнопки проверенного 8BitDo Micro (режим D) пока не работают. Bluetooth-аудио и подтверждение PIN не поддерживаются. Подробнее — в [ограничениях Bluetooth](docs/bluetooth.md).

## Компоненты

- Каталог библиотеки и сохранение настроек с восстановлением после ошибки записи.
- Английская и русская локализация; английский используется при отсутствии перевода.
- Общие SDL-компоненты отрисовки, типографика, иконки и подсказки клавиатуры/контроллера.
- Компактный индикатор громкости: подтверждённый уровень, отключённый звук, ожидание и ошибка.
- Запуск NES (FCEUmm), Game Boy / Game Boy Color (Gambatte), Game Boy Advance (gpSP) и экспериментальные Super Nintendo (Supafaust) и Mega Drive / Genesis (PicoDrive) через отдельный процесс с закреплёнными версиями ядер.
- Сохранение SRAM и часов картриджей GB/GBC (RTC), ручные слоты с кадром игры и продолжение с сохранённого состояния.
- Библиотека, избранное, настройки и меню игры.
- Модельные тесты, проверки отрисовки и сценарии запуска/сохранения/продолжения без окна.
- Выбор часового пояса по странам и городам с локализацией и быстрыми переходами.
- Заполнение батареи по заряду, состояния зарядки/неизвестного уровня и отключаемые проценты.
- Сон при закрытии крышки и пробуждение по Power; пробуждение от открытия пока недоступно.
- Настройка Wi-Fi на H700: отдельный поиск сетей, восстановление подключения, IP и уровень сигнала.
- Автоматическая и разовая синхронизация времени, ручная установка без сети с проверкой системных и аппаратных часов (UTC).

В «Недавних» хранятся 20 последних успешных запусков. Отдельное автосохранение
при выходе не меняет ручные слоты; после включения предлагается продолжить игру.
Есть общий целочисленный масштаб с исключениями для игр и выбор фона с образцом
цвета, таймер гашения экрана в меню и тихие предупреждения о заряде в игре.
Подробнее: [автосохранение](docs/autosave.md), [настройки изображения](docs/display.md),
[питание](docs/power.md).

На RG34XXSP проверены игры GB/GBC, сохранения, продолжение и сон. Подробнее: [Game Boy](docs/game-boy.md).

На RG34XXSP проверены игры GBA, сохранения, продолжение и сон. Подробнее: [GBA](docs/game-boy-advance.md).

На RG34XXSP проверены игры SNES, сохранения и продолжение. Нажатия кнопок и изменение громкости больше не прерывают игру и звук; удержание кнопки громкости повторяет регулировку. Подробнее: [SNES](docs/super-nintendo.md).

Mega Drive: Y/B/A приставки → A/B/C Sega, L1/X/R1 → X/Y/Z, Select → Mode. Клавиатура и ограничения: [Mega Drive](docs/mega-drive.md). Общая библиотека сортируется по названию без группировки по платформам; «Недавние» сохраняют порядок запусков.

В **Настройки → О системе** доступны устройство, установленное ПО, карты памяти и питание; X раскрывает полное значение и источник. Подробнее: [сведения о системе](docs/system-information.md).

На RG34XXSP с BaseOS 1.5.2 проверены игры Mega Drive, сохранения, продолжение, сон и экран «О системе».

Добавлена экспериментальная PlayStation/PCSX ReARMed: только CHD и CHD-плейлисты, встроен OpenBIOS; свой BIOS или HLE выбираются в разделе «Настройки ядер → Sony PlayStation». [Настройка и ограничения](docs/playstation.md). Проверено на RG34XXSP с BaseOS 1.5.2.

**Формат состояний:** в 0.9.0 все ядра используют компактные бинарные состояния. Старые JSON-состояния не загружаются и не удаляются; внутриигровые SRAM/RTC и карты памяти PSX сохраняют формат. Подробнее: [автосохранения](docs/autosave.md).

Для режима **«BIOS пользователя»** положите свои файлы размером 512 КиБ в `RondoState/BIOS/PSX`, с именами из таблицы. Прошивки Sony в архивы Rondo не входят.

| Имя файла | BIOS | Проверка |
| --- | --- | --- |
| `psxonpsp660.bin` | Прошивка PS1 из PSP 6.60 | Известный MD5, запуск игры на Mac проверен |
| `scph101.bin` | PSone, Северная Америка | Известный MD5, запуск игры на Mac проверен |
| `scph7001.bin` | PlayStation, Северная Америка | Известный MD5, запуск игры на Mac проверен |
| `scph7502.bin` | PlayStation, Европа | Запуск игры на Mac проверен |
| `scph1001.bin`, `scph5500.bin`, `scph5501.bin`, `scph5502.bin` | Другие розничные версии BIOS PlayStation | Имена поддерживаются; в этом прогоне не проверялись |

На карте используйте имена строчными буквами. В пункте **«Файл BIOS»** можно оставить **«Автоматически»** или выбрать конкретный найденный образ; режим в **«Настройки ядер → Sony PlayStation»** применяется при следующем запуске игры. Встроенный OpenBIOS остаётся вариантом по умолчанию. [Контрольные суммы и выбор BIOS](docs/playstation.md#bios-files).

## Разработка

Нужны компилятор C++17, make, pkg-config, SDL2, SDL2_ttf и Python 3.11+.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/requirements.txt
.venv/bin/python tools/build_core.py
.venv/bin/python tools/check.py --work build/native-check
```

Обычная сборка создаёт build/rondo. Все пять ядер собираются отдельно из исходников: загрузки проверяются по SHA-256, версии закреплены в docs/dependencies/core-source.json, gb-core-source.json, gba-core-source.json, snes-core-source.json и md-core-source.json. Команда проверки собирает приложение и запускает проверки исходников, модели, отрисовки, сохранения/продолжения NES/GB/GBC/GBA/SNES/MD и политики сна с dummy-драйверами видео и звука и собственным тестовым картриджем. Каталог build/native-check должен быть новым; без --work временный каталог создаётся автоматически. В нём сохраняются журналы, кадры и summary.json. Тесты не обращаются к SD-карте и не подтверждают работу физических кнопок, яркости или сна устройства.

GitHub Actions выполняет эти проверки на Ubuntu и macOS при push в dev/main и для pull request. Workflow имеет права только на чтение; внешние actions закреплены полными хешами коммитов.

## Запуск на компьютере

```sh
PYTHON=.venv/bin/python sh tools/demo.sh
```

Команда открывает окно и воспроизводит звук тестового картриджа. Библиотека и сохранения демо находятся в build/demo; путь можно задать через RONDO_DEMO_DIR.

В меню: стрелки, Enter/Z — выбор, Esc/X — назад, C — избранное/информация, V — поиск, Tab — настройки, Q/E — раздел, Tab в игре — меню игры, =/- — громкость. В NES/GB/GBC/GBA/SNES: Z/X — A/B, Enter — Start, Right Shift — Select; Q/E — L/R для GBA и SNES; S/A — X/Y для SNES.

Коммерческие ROM, фирменные BIOS и пользовательские сохранения в репозиторий не входят.

## Тестовый пакет H700

Нужен Docker с поддержкой Linux ARM64. Две сборки в новых каталогах позволяют сравнить идентификатор исходников, поставляемые бинарные файлы и хеш ZIP:

```sh
python3 tools/build_h700_runtime.py --work build/h700-first
python3 tools/build_h700_runtime.py --work build/h700-second
```

Пакет рассчитан на RG34XXSP с BaseOS 1.3.0. В него входят фронтенд, закреплённый runtime, собственный тестовый картридж, соответствующие исходники и лицензии. Это ZIP фронтенда для установленной BaseOS, а не загрузочный образ SD. Сборщик не обращается к карте. [Установщик для macOS](docs/installation.md) сохраняет оригинал загрузочной картинки и применяет логотип Rondo до первого запуска фронтенда, если замена не отключена в существующих настройках.

Проверка пакета и необязательный изолированный прогон BaseOS описаны в [руководстве runtime](runtime/README.md). Границы проверок — в [совместимости](docs/compatibility.md), резервное копирование и откат — в [ручной установке](docs/installation.md). GPL-ядра сохраняют требования к исходникам; PicoDrive — некоммерческие условия. Код и оригинальная графика Rondo остаются MIT. Подробнее — в [аудите поставки](docs/shipping-audit.md).
