# Rondo

[English](README.md)

Личный проект фронтенда для Anbernic RG34XXSP. Приставка мне очень понравилась, а подходящего для себя фронтенда я не нашёл — поэтому начал делать Rondo.

**Ранняя разработка.** Интерфейс и формат настроек могут меняться.

## Компоненты

- Каталог библиотеки и сохранение настроек с восстановлением после ошибки записи.
- Английская и русская локализация; английский используется при отсутствии перевода.
- Общие SDL-компоненты отрисовки, типографика, иконки и подсказки клавиатуры/контроллера.
- Компактный индикатор громкости: подтверждённый уровень, отключённый звук, ожидание и ошибка.
- Запуск NES через отдельный процесс с закреплённой версией ядра FCEUmm.
- Сохранение SRAM, ручные слоты с кадром игры и продолжение с сохранённого состояния.
- Библиотека, избранное, настройки и меню игры.
- Модельные тесты, проверки отрисовки и сценарии запуска/сохранения/продолжения без окна.

## Разработка

Нужны компилятор C++17, make, pkg-config, SDL2, SDL2_ttf и Python 3.11+.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/requirements.txt
.venv/bin/python tools/build_core.py
.venv/bin/python tools/check.py --work build/native-check
```

Обычная сборка создаёт build/rondo. Ядро собирается отдельно из исходников: загрузка проверяется по SHA-256, версия закреплена в docs/dependencies/core-source.json. Команда проверки собирает приложение и запускает проверки исходников, модели, отрисовки, сохранения/продолжения NES и политики сна с dummy-драйверами видео и звука и собственным тестовым картриджем. Каталог build/native-check должен быть новым; без --work временный каталог создаётся автоматически. В нём сохраняются журналы, кадры и summary.json. Тесты не обращаются к SD-карте и не подтверждают работу физических кнопок, яркости или сна устройства.

GitHub Actions выполняет эти проверки на Ubuntu и macOS при push в dev/main и для pull request. Workflow имеет права только на чтение; внешние actions закреплены полными хешами коммитов.

## Запуск на компьютере

```sh
PYTHON=.venv/bin/python sh tools/demo.sh
```

Команда открывает окно и воспроизводит звук тестового картриджа. Библиотека и сохранения демо находятся в build/demo; путь можно задать через RONDO_DEMO_DIR.

В меню: стрелки, Enter/Z — выбор, Esc/X — назад, C — избранное/информация, V — настройки, Q/E — раздел, Tab — меню игры, =/- — громкость. В NES: Z/X — A/B, Enter — Start, Right Shift — Select.

Коммерческие ROM, BIOS и пользовательские сохранения в репозиторий не входят.

## Тестовый пакет H700

Нужен Docker с поддержкой Linux ARM64. Две сборки в новых каталогах позволяют сравнить идентификатор исходников, четыре бинарных файла runtime и хеш ZIP:

```sh
python3 tools/build_h700_runtime.py --work build/h700-first
python3 tools/build_h700_runtime.py --work build/h700-second
```

Пакет рассчитан на RG34XXSP с BaseOS 1.3.0. В него входят фронтенд, закреплённый runtime, собственный тестовый картридж, соответствующие исходники и лицензии. Это ZIP фронтенда, а не загрузочный образ SD или опубликованный бинарный релиз. Сборщик не обращается к карте.

Проверка пакета и необязательный изолированный прогон BaseOS описаны в [руководстве runtime](runtime/README.md). Границы проверок — в [совместимости](docs/compatibility.md), резервное копирование и откат — в [ручной установке](docs/installation.md).
