# RG34XXSP display and suspend adapter

This adapter targets BaseOS1.3.0 RG34XXSP only. macOS and other profiles remain unsupported. No BaseOS kernel/rootfs change or NextUI runtime is required.

Brightness uses the vendor disp2 ABI on `/dev/disp`: GET0x103, SET0x102, `unsigned long args[4]` with display0 and raw brightness in args[1]. Twenty-one steps cover0–100% in5% increments, interpolating the original4,6,10,16,32,48,64,96,128,192,255 curve. Points through90% stay identical;95% maps to224 and100% to254 to avoid the vendor remapping of255. The minimum remains visible. Writes are read back before persisting; a persistence failure attempts to restore the prior hardware value. A fresh configuration adopts the actual hardware brightness instead of overwriting it with a guessed default.

Only the active process owns PMIC Power input. It finds the axp*-pek evdev device by name/capabilities, ignores repeats and requires a fresh press/release. The shell closes input while supervising a runner; its background boot-logo acknowledgement must not also poll the lid. Hall state is read at most every100ms from `/sys/class/power_supply/axp2202-battery/hallkey`:0 closed,1 open. Lid sleep defaults to On and is independently switchable; Power sleep remains available when lid sleep is Off.

Before suspend, the active process pauses the core, clears held input and queued audio, flushes SRAM and fully closes SDL audio. A failed SRAM write aborts suspend. Pending boot-logo work finishes before sleep. Manual save slots are never overwritten by sleeping: live emulation remains in suspended RAM.

The device adapter saves the ALSA mixer through bounded alsactl, blanks the backlight/framebuffer, updates the work LED, flushes filesystems, applies SP Super Standby16 where exposed and writes `mem` to `/sys/power/state`. A suspend write is never blindly retried. A Power wake while the lid is closed re-enters sleep. Once the lid is open, mixer/display are restored before SDL audio is reopened; fresh input readers discard the wake key. Core/menu/Info focus is preserved. Failed suspend restores the display and keeps gameplay paused with an error; it never escalates to poweroff.

Current BaseOS Super Standby wakes through Power. Opening the lid alone does not wake it: open, then press Power. Long hardware power holds can still force power-off; abrupt power loss does not guarantee live RAM progress.

Tests cover injected hardware/authority/storage failures, fresh Power semantics, lid policy and active-process ownership, core-state continuity, dummy-audio close/reopen and old/new save envelopes. The native H700 protocol is exercised in an isolated BaseOS chroot with synthetic sysfs, fake disp2 ioctl and fake alsactl. It checks visible minimum/readback, closed-lid re-suspend and restore after a failed mem write. These tests do not prove the actual kernel suspend, panel or sound after physical wake; those require RG34XXSP feedback.

Brightness diagnostics use `[brightness]` records in RondoState/launcher.log, with monotonic milliseconds and PID. They record requested percent/raw, set ioctl result/errno, get value/errno and exact readback comparison. Out-of-range reads retain their actual value in diagnostics. Kit08 device logs showed requested255/returned200. Analysis of the exact RG34XXSP vendor kernel revealed explicit ioctl remapping:255 to200 and200 to170. Kit09 requests254 at100%;95% remains224 and90% remains192, with5% UI steps. Strict equality checks stay enabled. The raw254 endpoint still requires physical brightness, reboot-persistence and sleep/wake acceptance checks.
