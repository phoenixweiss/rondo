# Library artwork cache

Library navigation requests artwork asynchronously. One worker reads and decodes
PNG files, then prepares a thumbnail for the 204×204 preview area. The selected
image has priority; up to four neighbouring games are prefetched. Changing focus
cancels stale queued work. A neutral placeholder is displayed while loading;
missing-artwork text appears only after the request fails.

Original `cover.png`, `title.png` and `screenshot.png` files are never modified.
The library worker is destroyed before the game process starts; the game runner
does not create an artwork worker. Save-slot previews keep their separate compact
state format and are not regenerated by this cache.

## Files and limits

- Files live under `RondoState/Cache/Artwork/`.
- A filename is 64 lowercase SHA-256 characters plus `.rgba`. The hash identifies
  the source path, file size, modification time, requested dimensions, filtering
  and cache-format version. It is not the original PNG's content hash: checking a
  cache entry does not require rereading the entire source image.
- Each thumbnail fits within 204×204, preserving aspect ratio. Small originals
  are not enlarged on disk. Covers use alpha-aware linear filtering; title and
  screenshot previews use nearest-neighbour sampling.
- The file contains an 80-byte version/dimensions/checksum header followed by
  uncompressed RGBA pixels. Maximum size is 166,544 bytes (about 163 KiB).
  Persistent reads avoid another PNG decode.
- Decoded images and SDL textures each have a 4 MiB LRU budget. Completed disk
  entries have a 32 MiB budget. Disk LRU uses current-session accesses, with file
  timestamps providing the initial order after restart. Temporary writes add at
  most one bounded thumbnail while being replaced.
- Source metadata is checked in the worker at most once a second while selected.
  PNGs are limited to 4096 pixels per dimension and 16 MiB of encoded data.
  The worker's temporary decoder allocation is separate from the resident cache.

Cache writes use a temporary file and atomic rename, without the save-state
fsync policy. The cache is disposable: corrupt entries are regenerated. A full,
read-only or unavailable cache directory falls back to decoded images in RAM.
Unchanged invalid PNGs are not decoded repeatedly. Cache symlinks are not followed.
With Rondo closed, the Artwork cache directory can be removed to rebuild it.
ROMs, original artwork, saves and preferences do not need to be removed.
